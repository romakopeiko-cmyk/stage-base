# Stage Base Staging

Адреса застосунку — https://romakopeiko-cmyk.github.io/stage-base/staging/
Проєкт Supabase — `cnkwvrxlvvtmfiubtyks`.

## Перший адміністратор

1. У Supabase Dashboard для **Stage Base Staging** у **Authentication → URL Configuration** додайте точну адресу застосунку до перенаправлень і встановіть її як Site URL. Переконайтеся, що відкрито саме Staging.
2. У **Authentication → Users → Add user → Create new user** створіть один акаунт із підтвердженою адресою та унікальним паролем з менеджера паролів. Підтвердіть email лише після перевірки, що скринька належить адміністратору.
3. Повідомте розробнику, що обліковий запис створено. Роль виконавчого продюсера в Staging призначається один раз за точним UUID підтвердженого Auth-акаунта. Системна перевірка має підтвердити, що активного адміністратора ще немає. Пароль залишається в менеджері паролів.
4. Увійдіть у Staging та відкрийте **Профіль → Команда**. Запросіть спочатку одного працівника на контрольовану тестову адресу. Після прийняття запрошення працівник встановлює пароль у профілі.

Вбудований SMTP Supabase має обмеження одержувачів і частоти. Для зовнішніх адрес використовуйте погоджений SMTP. Ключі Auth і SMTP зберігайте тільки в налаштуваннях сервера.

## Межі перевірки

Міграції `staging_team_workflows` і `staging_team_access` розраховані на окрему схему Staging. Персональні обмеження звужують базовий доступ. Для перенесення у робочий проєкт потрібно звірити всі RLS, RPC, типи документів і чинний реєстр дозволів.

Обмеження активності перевіряється базою та Storage для вже виданих токенів. Раніше видані підписані URL живуть до завершення свого строку. Переносити їхній механізм у нові інтерфейси слід лише після перевірки правил доступу.

Передавання охоплює відкриті командні завдання з доступним шоу. Завершені завдання, авторство та зовнішні складські операції зберігають свою історію.
