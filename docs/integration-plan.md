# Інтеграція складських операцій, команди та сповіщень

## Доступна версія

Випуск 2.1.0 відкриває «Завдання» після входу. Каталог містить статистику, бронювання, довідник шоу та складів і, для відповідних ролей, чергу уточнення. Профіль показує версію. PWA перевіряє наявність нового Service Worker при відкритті та поверненні у видиму вкладку. Підготовлене оновлення активується після натискання «Оновити». Відкриті форми захищені від перезавантаження. Навігація повторно перевіряє мережеву версію, а приватні дані не зберігаються в Cache Storage.

## Пакет робочих процесів

| PR | Серверні залежності | Умова приймання |
|---|---|---|
| №7, рухи та системні перевірки | Чинні каталог, бронювання, імпорт, перевірки й особисті завдання | QR, права, фізичне приймання, дробова кількість, фото та завершення автоматичного завдання |
| №10, командні завдання | Чинні особисті завдання, профілі, шоу та сповіщення | Призначення в межах шоу, відкликання доступу, окремий захист дедлайну |
| №13, обговорення й підзавдання | Особисті завдання; для командних сценаріїв спочатку №10 | RLS успадковується від картки. Чужі коментарі й підзавдання закриті |
| №12, Web Push | Чинний inbox, приватна черга, Edge Function, VAPID і серверний планувальник | Доставка на закриту PWA на реальному пристрої; клік відкриває inbox |

Міграції перевіряються разом в ізольованому середовищі. PR №7 обмежує редакцію системних завдань, а PR №10 додає окрему обмежувальну політику для шоу. Клієнтські гілки перетинаються в `index.html` і `tasks.js`. Перед випуском об’єднати їх в одну інтеграційну гілку, зберегти навігацію 2.1.0, обидва обмеження доступу та обробники оновлення і Push в одному Service Worker. Скласти єдиний diff і повторити тести, перш ніж опублікувати клієнт.

1. Звірити реєстр, чинну схему й ізольований сценарій усіх міграцій. Підготувати резерв і перевірити відновлення.
2. Отримати погодження робочих міграцій. Серверний порядок — №7, №10, №12, №13 за версіями реєстру. Перевірити обидва обмеження RLS після цього порядку. Push можна лишити вимкненим до наявності секретів і планувальника.
3. Перевірити робочі RPC, права й сумісність попереднього клієнта. Розгорнути інтегрований клієнт, код якого відповідає застосованим міграціям. Перевірити старт, каталог, QR, завдання, вихід і оновлення на iPhone.
4. Завантаження виробничого каталогу є окремою дією після погодження даних. Перевірки і навчання проводити на тестових даних.

## Резервування з iPad

Для повного Free-резерву найпростіше доручити дамп довіреному оператору з комп’ютером, який має доступ до PostgreSQL Session pooler. Власник може погодити це з iPad, без встановлення CLI на планшет. Оператор робить зашифрований дамп і перевіряє відновлення в ізоляції. Значення секретів залишаються в захищеному обміні, резерв — поза GitHub. Експорт через Safari з Dashboard придатний як часткова копія таблиць і файлів, а не як умова випуску SQL. Див. [інструкцію](manual-backup.md) та [реєстр](migration-register.md).
