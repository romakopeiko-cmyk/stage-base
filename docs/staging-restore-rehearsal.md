# Відновлення Stage Base Staging

1. Перевірте контрольну суму зашифрованого архіву з iCloud Drive. Зберігайте архів і ключ у захищеному середовищі.
2. Підготуйте локальний Supabase з відповідною основною версією PostgreSQL. Використайте окрему базу й перевірте, що підключення не веде до хмарного проєкту. Відключіть зовнішні поштові інтеграції.
3. Перегляньте склад дампа через `pg_restore --list` після розшифрування в захищеному локальному середовищі. Звірте прикладні схеми, Auth, історію міграцій, RLS і гранти. Для SQL-дампа перегляньте команди створення ролей і схем перед виконанням.
4. Відновіть копію в порожній базі або в підготовленій локальній інсталяції. Для інсталяції з наявними керованими об’єктами Supabase розділіть відновлення за переліком об’єктів. Зупиніться на помилці та перевірте конфлікт. Не використовуйте хмарні URL для відновлення.
5. Звірте кількості записів, UUID профілів і зв’язки з Auth локально. Перевірте вхід синтетичним акаунтом, RLS та права на файли. Видаліть тимчасові розшифровані файли після перевірки.

## Приватні файли

Окремо скопіюйте байти об’єктів усіх чотирьох приватних бакетів через авторизований Storage API. Збережіть бакет, шлях, розмір і SHA-256 у зашифрованому маніфесті. Під час репетиції завантажте об’єкти в локальні приватні бакети через Storage API, звірте контрольні суми та перевірте доступ штатними ролями. SQL-дамп містить метадані Storage, а файлові байти зберігаються окремо.
