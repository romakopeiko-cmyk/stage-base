# Web Push Stage Base

Черга формує одне завдання на сповіщення та підписку. Серверний воркер бере завдання з обмеженим строком оренди, надсилає стандартний зашифрований Web Push, повторює тимчасові помилки та вимикає підписки після HTTP 404/410. Зміст повідомлення на екрані блокування загальний. Після натискання відкривається центр сповіщень.

## Підключення

- Згенерувати окрему пару VAPID і секрет виклику воркера поза GitHub. У Supabase Edge Function Secrets задати `STAGE_PUSH_PUBLIC_KEY`, `STAGE_PUSH_PRIVATE_KEY`, `STAGE_PUSH_CONTACT` і `STAGE_PUSH_WORKER_KEY`. Службовий ключ читається з серверного середовища.
- Після дозволеного застосування міграції розгорнути `push-dispatch`. Захищений серверний планувальник має робити POST до функції приблизно щохвилини з `x-stage-worker-key`. Якщо gateway вимагає JWT, налаштувати його на сервері. Для планування через Supabase Cron/pg_net значення заголовків зберігати у Vault. Публічний браузер не викликає воркер.
- Вписати лише публічний VAPID-ключ у `push-config.js`. Без нього інтерфейс підписки прихований.
- На iPhone/iPad із підтримкою Web Push відкрити вже встановлену PWA, перейти у профіль та натиснути «Увімкнути Push на цьому пристрої». Після створення тестового повідомлення закрити PWA, зафіксувати отримання та перевірити відкриття центру сповіщень. Окремо перевірити відмову в дозволі, вихід з акаунта та недійсну підписку.

Пакет переносить наявні повідомлення центру сповіщень у Web Push. Серверні нагадування за дедлайнами, власний графік, відкладення й дайджест потребують окремих джерел подій. На момент підготовки міграцію, воркер і планувальник до робочого проєкту не застосовано.
