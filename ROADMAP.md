# Stage Base 1.0 Release Candidate

Поточна робота зосереджена на безпеці чинного Staging і сумісності інтеграційної збірки. Віддалене розгортання Release Candidate ще не виконано.

## Підтверджена основа

| Напрям | Стан | Наступна перевірка |
| --- | --- | --- |
| PR №31, права профілів, завдань, сповіщень та каталогів | На PostgreSQL 17 відтворено 20 міграцій Staging і застосовано три міграції PR. Збіглися імена 25 прикладних таблиць, типи, порядок і обов’язковість колонок. | Запустити підготовлені Auth, REST та Storage тести в повному локальному стеку. |
| SECURITY DEFINER | 26 функцій пройшли SQL-перевірку для сесії без профілю та деактивованого адміністратора. | Додати позитивні сценарії для кожної функції та перевірити кожну делеговану дію. |
| Каталог, шоу, склади, файли та QR | Локальні SQL і браузерні перевірки каталогу пройшли. Браузерні тести використовували змодельований API. | Хмарний приймальний прогін із приватними файлами, телефоном і реальними правами. |
| Команда, запрошення, завдання, чеклісти, сповіщення | У чинному Staging є робочі модулі. Зміни доступу підготовлено в PR №31. | Перевірити листи, відновлення пароля, деактивацію з чинним JWT, вкладення і Push. |
| Бронювання, календар, видача, підтвердження, повернення, рух і перевірка | Використати чинні серверні міграції та інтеграційний PR №30. Повний складський цикл має локальне SQL-покриття. | Перевірити цілісний користувацький сценарій та одночасні дії після інтеграції. |
| Комплекти, витратні матеріали, відповідальні та історія | Серверні частини перевірено ізольованими тестами. | Пройти наскрізні сценарії за ролями та звірити незмінність журналу. |
| Інвентаризація, ремонти, списання, компенсації, звіти й налаштування | Готовність до релізу не підтверджена. | Звірити наявні серверні компоненти, допрацювати відсутні потоки й експорти PDF/Excel. |
| Імпорт каталогу | Наявні напрацювання попереднього перегляду, валідації та повторного імпорту. | Прогнати імпорт синтетичної книги, підготувати звіт на погодження перед записом реальних даних. |
| ШІ-пошук та розпізнавання | Готовність не підтверджена. | Перевірити зовнішню залежність, серверне обмеження доступу та налаштування провайдера. |

## Порядок продовження

1. Прогнати `tools/security/staging-definer-matrix.sql`, `staging-postgres-matrix.sql` та ACL-перевірки. Повторне використання відтвореної історії усуває потребу повторно завантажувати метадані.
2. Запустити Auth, REST та Storage на Docker-хості з достатнім диском за `docs/staging-security-test-stack.md`. Поточний хост зупиняє розпакування образу PostgreSQL через нестачу місця. Прогнати повну матрицю прав із синтетичними акаунтами й позитивними перевірками. Звірити Security Advisor після погодженого розгортання.
3. Завершити перевірку інтеграції PR №30, повторно перевірити RLS, приватні файли, конкурентне бронювання та відкат. Перемикання чинного Staging вже було відхилено автоматичною перевіркою. Повернутися до нього після перевіреного відновлення й усунення причин відмови.
4. Завершити модулі та провести приймання на iOS, Android, планшеті й ПК. Окремо перевірити великий каталог, фото, локалізацію, помилки та PWA. Підготувати інструкції для адміністратора, комірника й співробітника.
5. Відновити зашифровану копію та Storage у відокремленому середовищі, зафіксувати процедуру, опублікувати RC лише в Staging після перевірок. Production потребує окремого погодження. Реальний імпорт потребує окремого підтвердження.

Приватні міграції, копії баз і ключі зберігаються поза репозиторієм.
